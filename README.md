Player notes: the final picture (fx12) stays on screen until the end of the music. Found in the original code (re/NOTES.md "End of the demo"): fx12 ends with `cmpw $0x3b,[0x3575]; jne` (flat 0x7abed) and then would set text mode and exit, but with the GUS player [0x3575] and [0x3576] both hold the order, so the word compared is 0x3b3b, never 0x3b: the original never leaves fx12 (no key check either), and its music loops to order 0 after order 62 (S3M loader strips the 0xff marker, wrap at 63). The earlier "black tail after ~224 s" was an error of the port (it assumed the harness' no-sound counting, where [3576] stays 0). The port stops at the end of the S3M (250.4 s) instead of looping. Animation phase at a given music time can differ from the oracle's frames in several effects (fx4, 5, 7-11): the ISR is derived to tick once per vsync (software PLL, see NOTES) and every pass loop ends with a retrace wait, so on a CPU fast enough for a pass to fit one frame (the port's assumption) there is one tick and one pass per vsync; the harness (Unicorn, 12 MIPS, 3DA/PIT model) needs 2-3 vsyncs per pass, so its per-pass state differs; the "0 differing px" checks use the harness's per-pass state. Whether a 1995 CPU met the one-pass-per-frame condition for each effect is not derivable (fx0: 3..6 ticks per pass even in the harness).
