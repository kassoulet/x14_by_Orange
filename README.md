# x14 - "X14" (Orange, 1995, winner of Juhla 2)
Port status: **phase 3 in progress: 8 of 13 effects ported to JS (fx3 "logo text", fx4 "tunnel", fx5 "feedback plasma", fx6 "picture + fade", fx7 "colour ring", fx8 "organic blob", fx9 "terrain", fx10 "warped quad"), each checked with 0 differing pixels/palette bytes against the Unicorn run of the original (fx6: palette 127/128, see NOTES); the other 5 show a placeholder in the player.** Code Hoplite, music Dune (X14.S3M), graphics Der Piipo. Original files untouched.
Files: X14.EXE (130 KB, PKLITE real-mode 386 program that switches itself to 32-bit protected mode with its own extender), DATA.DAT (932 KB, blobs read by absolute/from-the-end offsets), X14.S3M, INFOFILE, FILE_ID.DIZ. Needs 386+, GUS optional. `AO070295.EXE` = copy of an unrelated small executable, not analysed.
Run: `cd web && python3 -m http.server 8000`; tests: `node web/test-player.mjs`, `node tools/uitest.mjs` (headless chrome: play/pause/seek, the two ported effects), `node tools/fxcheck.mjs FX PREFIX`, `node tools/fxcheck8.mjs PREFIX` (diff against the oracle, see re/NOTES.md).
Bit-exact (vs the harness, 0 differing bytes): fx3 palette (every upload and hold, 128 uploads) and the 320x240 indexed picture; fx6 picture exact and palette exact on 127 of 128 sampled steps; the 128th differs because the harness itself uploaded one fade-out step 0.93 vsync late (virtual-clock artifact, see re/NOTES.md), the port keeps ideal pacing. Everything the effects do with time is a pure function of t.
Approximated / UNRESOLVED (see re/NOTES.md): (a) the entry time of fx3 and fx6 and the vsync phase are the harness' virtual-clock measurements (IPS 12e6, 3DA model 70.086 Hz), not derived: on real hardware they depend on CPU/disk; (b) the music clock is libopenmpt's, the oracle check used the harness' own S3M model (0.07 % different); (c) the CRTC line-compare split was added to the harness' display but is not validated on an original frame; (d) IRQ0 is injected between 2000-instruction chunks, not per instruction; (e) fx7/fx9 are validated against the oracle with the harness' own schedule (ticks per pass); the player assumes one ISR tick and one pass per vsync (real ratio depends on the CPU), mid-pass ISR races are accepted only when one switch point reproduces the oracle; (f) fx9's unwritten VRAM rows (16 above, 17 below the picture) are shown black as in the harness, real VRAM content unknown; (g) fx4: the tunnel image, scroll and palette match the oracle in 357 of 547 records; the other 190 differ only on a few top rows (scatter caught mid-draw by the harness capture) or by one tick (harness ticks 2 per pass), and the pre-tunnel phase (start picture on a black DAC) is unverified; (h) fx5: the pixels match the oracle in all 199 passes (VRAM feedback resynced per pass), the palette fade is off by a few 1-LSB entries in 144 passes (the harness ISR ticks while the upload loop runs, 3 ticks per pass) and the tick simulation differs by one tick in 67 passes (harness interrupt timing); (i) fx10: pixels match the oracle in all 416 passes (texture/buffer feedback accumulated from the first loop top), the palette fade differs in 73 passes (harness ticks 1-3 per pass, an upload interleaved with a tick); (j) effects 0-2, 8, 10-12 are not ported (not classified for seek beyond the phase-1 remarks).
Seek: fx3, fx6 pure functions of t. Show 4:3 (fx3 is a 320x240 mode, fx6 320x200, both shown in the 4:3 box), player has pause + seek. See `re/NOTES.md`.
