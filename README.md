# x14 - "X14" (Orange, 1995, winner of Juhla 2)
Port status: **phase 2: 2 of 13 effects ported to JS (fx3 "logo text" and fx6 "picture + fade"), checked against the Unicorn run of the original; the other 11 show a placeholder in the player.** Code Hoplite, music Dune (X14.S3M), graphics Der Piipo. Original files untouched.
Files: X14.EXE (130 KB, PKLITE real-mode 386 program that switches itself to 32-bit protected mode with its own extender), DATA.DAT (932 KB, blobs read by absolute/from-the-end offsets), X14.S3M, INFOFILE, FILE_ID.DIZ. Needs 386+, GUS optional. `AO070295.EXE` = copy of an unrelated small executable, not analysed.
Run: `cd web && python3 -m http.server 8000`; tests: `node web/test-player.mjs`, `node tools/uitest.mjs` (headless chrome: play/pause/seek, the two ported effects), `node tools/fxcheck.mjs FX PREFIX` (diff against the oracle, see re/NOTES.md).
Bit-exact (vs the harness, 0 differing bytes): fx3 palette (every upload and hold, 128 uploads) and the 320x240 indexed picture; fx6 picture exact and palette exact on 127 of 128 sampled steps; the 128th differs because the harness itself uploaded one fade-out step 0.93 vsync late (virtual-clock artifact, see re/NOTES.md), the port keeps ideal pacing. Everything the effects do with time is a pure function of t.
Approximated / UNRESOLVED (see re/NOTES.md): (a) the entry time of fx3 and fx6 and the vsync phase are the harness' virtual-clock measurements (IPS 12e6, 3DA model 70.086 Hz), not derived: on real hardware they depend on CPU/disk; (b) the music clock is libopenmpt's, the oracle check used the harness' own S3M model (0.07 % different); (c) the CRTC line-compare split was added to the harness' display but is not validated on an original frame; (d) IRQ0 is injected between 2000-instruction chunks, not per instruction; (e) effects 0-2, 4, 5, 7-12 are not ported (not classified for seek beyond the phase-1 remarks).
Seek: fx3, fx6 pure functions of t. Show 4:3 (fx3 is a 320x240 mode, fx6 320x200, both shown in the 4:3 box), player has pause + seek. See `re/NOTES.md`.
